Features

Give each bot a job.
It keeps doing it.

A bot is a persistent teammate with its own instructions, model, workspace, skills and memory. Conversations belong to it, and routines run it while you're away.

Nothing happens without a yes

Every file, command, network and MCP action an agent asks for is authorized by the gateway. Approve it once, for the task, or as a standing grant scoped to one folder or command. Revoke it any time.

file.read~/notes/**standing
commandgit log …standing
file.writedocs/CHANGELOG.mdasking
networkpypi.orgnever standing

Strict by default

Strict bots get no network, no processes and no filesystem. Their tools run in a Python sandbox behind bubblewrap namespaces and a seccomp filter. If isolation is missing, it fails closed.

$ sandbox check network denied subprocess denied seccomp locked

Routines that wait for you

Schedule a bot by interval, cron or once, and choose what happens after downtime. A run that needs approval notifies you and waits. It never proceeds or fails silently.

every 30mTriage inbox

Memory that carries over

Bots keep owner notes and their own remember / recall memory. Long sessions get summarized and archived, never deleted.

MCP and the browser

Attach MCP servers per bot behind an authenticated loopback proxy. One click adds headless browser automation with an isolated profile.

Skills you write

Drop a folder with a SKILL.md into your workspace and enable it per bot. It's added to that bot's instructions.

Reach it from anywhere you trust

Run the headless host on a server, pair your laptop with a one-time code, and approve requests from another machine. TLS 1.3 with a pinned certificate, Ed25519 device keys, and revocation that closes live connections.

$ your-bot-host pair pairing code 7KQ-M2X · expires in 10 min $ your-bot-remote approvals 1 waiting · Release Notes · file.write

        FAQ

        Questions,
        answered.

        More in the README and the security notes.

        Does anything leave my machine?

        Not by default. Conversations, settings and audit history live in local SQLite, and the default model endpoints are on loopback. Prompts only go elsewhere if you configure a remote model endpoint or run a trusted agent CLI that uses the network itself.

        Which models and agents can I use?

        Any local server that speaks the OpenAI chat API, including LM Studio and llama.cpp; ACP harnesses run in containment; and, per bot, an installed agent CLI such as Claude Code or Grok Build in trusted mode. Models need function calling to use skills.

        What's the difference between strict and trusted bots?

        Strict bots are fully contained: no network, processes or filesystem, with tools run in a sandbox. Trusted bots run an agent CLI with your user rights in the bot's workspace. Their file, terminal and permission requests still go through the gateway, but anything the agent does internally without asking isn't mediated.

        macOS says the app can't be opened

        Builds aren't notarized yet. Right-click Your Bot in Applications and choose Open, or run:

        xattr -dr com.apple.quarantine "/Applications/Your Bot.app"
        Windows SmartScreen blocks the installer

        Choose More info → Run anyway. PCs with Smart App Control turned on block unsigned apps with no override.

        What do I need on Linux?

        The strict sandbox needs Python 3 with venv, bubblewrap and gcc. The install script adds them for you. The AppImage needs FUSE 2.

        Can I run it without the desktop app?

        Yes. your-bot-host runs the gateway headless on Linux, macOS or Windows, and paired devices connect to it over TLS.
